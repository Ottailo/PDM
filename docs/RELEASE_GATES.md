## Independent security findings (source-confirmed, not live exploitation)
1. **HIGH: no customer staff-offboarding path.** `app/pilot/auth.py:269–330` lists members and creates/accepts invitations but provides no deactivation, role reduction or cancellation. `security.py:112–118` enforces active membership correctly, but owners cannot turn it off. A departed colleague keeps authorized access unless someone intervenes directly in the DB. Closure: tenant-scoped audited offboarding/demotion/invite cancellation, last-owner protection, immediate session denial and tests preserving other-factory memberships. Existing downloaded copies cannot be remotely erased.
2. **HIGH: cumulative document/storage/queue capacity is unbounded.** `documents.py:45–59` caps a single file, then writes and queues every accepted upload; `security.py:77–80` omits upload throttling. `worker.py:116` shares a time-ordered queue. A permitted technician can fill storage and delay email/other-factory jobs. Closure: enforced tenant storage/file/upload-rate/pending-job limits, transactional capacity reservations and fair scheduling or separate mail priority. Include quarantined and retained soft-deleted files in accounting; test concurrent limit races and one-tenant load without starving another.
3. **MEDIUM: user/token lock order can deadlock.** Verification/reset acquire token then user (`auth.py:118–119,145–146`); resend acquires user then updates tokens (`132–135`). Concurrent consumption/resend can form a PostgreSQL row-lock cycle and return generic500 after victim rollback. This is a traced structural risk, not an executed deadlock in this review. Closure: consistent lock order across token consume/resend, including invitation/company paths; deterministic concurrency tests prove no deadlock/duplicate action and intentional token validity.
4. **UNVERIFIED containment gate, not a demonstrated exploit:** `worker.py:70` isolated Python imports/sanitized env/timeouts and `pdf_parser.py:7–34` resource caps do not deny filesystem/network access or switch OS identity. If a parser defect allowed execution, worker permissions remain exposed. Closure: production restricted parser identity/container, narrowly mounted input/output, read-only root and denied egress, no application secrets available, explicit containment tests. No sandbox escape or parser exploit tested here.

The independent read-only review also confirmed existing tenant-scoped downloads, active-membership checks, one-use tokens/MFA replay protection, certificate-verified SMTP and scan-before-download. It found no reason to remove those controls. Completion of a source review is not certification or deployment sign-off. **Application code was not changed to fix these findings during this turn.**

## Gate 3 recovery contract
Restore must recover **records + files + necessary encryption keys + compatible code/schema**, not simply table names/counts. Current MFA secrets and queued action-link mail are encrypted with MFA_ENCRYPTION_KEY. Losing that key makes restored MFA/mail data unusable; storing it unencrypted beside a DB dump weakens separation. Backup and rotation need explicit access/restore rules.

Verify a scratch restore can sign in through MFA/recovery, retrieve a maintenance completion/event history, read/download an intact private PDF with matching checksum, and resume appropriate jobs without unintended recipient delivery. Exercise blob missing/corrupt, failed migration, down worker/scanner/SMTP, leaked credential and customer offboarding. Record elapsed recovery and newest recoverable transaction; RPO/RTO proposals need buyer agreement, not invented SLA claims.

## Gate 4 scope
Operator emails/names and labor/service records are personal data; machine manuals and process records can also be commercially sensitive. Document legal/controller-processor responsibilities, data access, retention, subprocessors and cross-border transfers with qualified advice. Store no customer data in the personal/free AI pool; AI is absent in Stage1.

PDF support currently means scanned-for-malware original plus extracted text; image-only manuals can have no text. OCR/AI/manual web discovery are not Stage1 features and must not be advertised. Downloads and exports already authorized are not remotely revocable copies.

## What does NOT block a maintenance-only pilot
Hardware integration, predictive models/RUL, AI assistant/mascot, MCP, inventory ERP, native phone/desktop distribution and saved drag/drop panels are later roadmap. Their absence must be stated, not represented by inactive or fake controls. Text PDFs, ordinary machines and human-driven maintenance are enough to test first value once gates 1–5 close. No equipment access means no monitored-equipment or failure-prediction sale.
